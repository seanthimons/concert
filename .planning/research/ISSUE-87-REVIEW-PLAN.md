When exactly one supplies an ID, lines 242 onward produce `single` and retain that ID without inspecting raw name semantics, multi-analyte warnings, row flags, or reviewer reasons. `set_row_flags()` (line 396) changes only row flags and reasons. A synthetic two-row base R reproduction using the reported name/CAS inputs and *injected*, not freshly retrieved, candidate IDs returned `single`, the CAS-selected identifier, FOLLOW-UP, and `.pinned = FALSE`. This demonstrates the code behavior, not correctness of either chemical assignment.

**Confirmed from source and an isolated exact-function reproduction:** `multi_analyte_separator_pattern()` (R/cleaning_pipeline.R:555) requires flanking spaces. Existing tests intentionally protect units, ratios, parenthetical groups, and stereochemical syntax.

**Source-confirmed export/consumer boundary:** `build_export_sheets()` (R/export_helpers.R:79) preserves consensus IDs while computing `needs_review` from errors/unresolvable status, FOLLOW-UP, incoming review requirements, and unreviewed WQX-only candidates. It does not currently treat `disagree`, unaccepted `suggested`, multi-analyte warnings, or BAD as a universal accepted-identity gate. Existing `test-export-review.R` deliberately says BAD alone is not a review requirement. Therefore `needs_review = FALSE` alone is insufficient for a new accepted-identity contract. Do not silently redefine that existing diagnostic.

`map_to_toxval_schema()` (R/toxval_mapper.R:119) copies `consensus_dtxsid`, falling back to `dtxsid`; it does not gate by flags or scope. This confirms an exposed generic consumer boundary, not demonstrated contamination in the pilot. The linked audit reports that the checked pilot helpers exclude FOLLOW-UP and require cleared review. Those downstream helpers were not independently replayed or inspected during this review, and no wrong identity entering a checked downstream path has been established.

Other material boundaries:

- `classify_auto_resolve()` only processes non-pinned disagree rows; an existing FOLLOW-UP or scope conflict does not itself prevent candidate scoring or pinning. Bulk suggestion acceptance likewise has no scope gate. Keep scoring useful, but prevent those actions from constituting scope acceptance.
- `resolve_review_row()` preserves source value and split lineage, but default broadcast repeats the source CAS across split children. Even position pairing allows one CAS to be repeated across several names. Splitting a multi-analyte row is therefore not sufficient to validate each child's identity.
- `keep_combined` clears the multi-analyte warning; it expresses a scope disposition, not proof that one component's CAS represents the combined source. A dedicated identity decision is still needed.
- `stage_review()` validates review-pick IDs for registry existence, then applies a Name(+optional CAS) content mask. Without CAS, repeated names across sources can all be changed. Registry membership proves neither source correspondence nor mixture scope.
- `pending_rows()` in R/curate_iterate.R exposes unresolved multi-analyte warnings even when flagged, but ordinary single/FOLLOW-UP scope and conflict rows fall outside its pick/no-match paths. Queue completion and identity eligibility must remain distinct concepts.

## Recommended contract

Implement an additive accepted-identity view and one documented eligibility helper while preserving lookup consensus and candidates. Proposed API names below are concrete design choices for implementation review, not existing exports:

1. `identity_review_state(df)` derives row-level `identity_status`, `identity_blockers`, `identity_eligible`, and `accepted_dtxsid`. `accepted_dtxsid` equals the selected consensus ID only when eligible; otherwise it is typed NA. A companion `accepted_identity_view(df)` returns only eligible rows with source lineage. `consensus_status = single` continues to mean one lookup source supplied an identifier and never claims that scope was independently resolved.
2. Eligibility requires a nonblank identifier, an allowed completed lookup/review outcome, no BAD or FOLLOW-UP flag, no incoming review requirement, no unresolved multi-analyte/scope/source conflict, and no unaccepted suggestion/disagreement/error/unresolvable status. Missing/unknown statuses fail closed. Preserve current ordinary clean agree/agree_caveat/single and completed manual/auto resolution behavior, subject to these blockers. A pinned suggested row with recorded explicit acceptance may qualify only after all blockers are resolved; `.pinned` alone is insufficient.
3. Keep WQX name-only acceptance separate: an accepted name-only view may exist, but it must not imply an accepted DTXSID. Preserve existing WQX review rules and never manufacture a DTXSID for WQX-only evidence.
4. Store explicit scope/source decisions in a structured record rather than extracting chemistry conclusions from prose reasons. Suggested persistent fields: `identity_scope` (substance, registered_mixture, aggregate/class, unknown), `identity_conflict` (none, scope, source_name_cas), decision action, reason, evidence reference, selected DTXSID when applicable, and evidence/content signature. An aggregate can be deliberately kept unresolved with no accepted DTXSID; do not require every row to be coerced to a single substance.
5. An unresolved structured conflict remains blocking after CLEAR, VERIFIED, manual ID entry, a high similarity score, or a keep/split action alone. Resolve scope and identity explicitly; clearing a general flag does not substitute for that decision. Existing FOLLOW-UP flags immediately block acceptance even before records are migrated. Do not globally treat every old VERIFIED or manual pick as verified scope.
6. Registered mixtures/extracts can become eligible when evidence establishes that the registered entity matches the source's combined scope and an explicit decision records that correspondence. Do not blacklist words such as mixture, oil, extract, polymer, or plural class names. An unmatched name and CAS-derived candidate is a review risk, not proof of conflict; name similarity or normalized string inequality cannot establish chemical disagreement.

Document the safe selection rule as `identity_eligible`, not nonblank `consensus_dtxsid` and not merely `!needs_review`. Retain all source/candidate fields in Curated Data for audit and add an explicitly named Accepted Identities sheet/view. Existing raw consensus exports remain compatible but their documentation and headings must describe them as lookup results.

## Implementation boundaries and order

1. **Pure shared policy:** add the eligibility and blocker derivation alongside R/consensus.R (or a focused R/identity_review.R). Unit-test missing columns, typed blanks, unknown statuses, precedence, and empty data. Keep candidate lookup classification separate from acceptance. Derived accepted fields must be recomputed, not replayed as authority.
2. **Structured decisions and lineage:** integrate with R/cleaning_pipeline.R and R/curate_stages.R. Reuse split/keep/rename machinery and audits. Preserve raw names/CAS, original row IDs, source values, child index/count, original source evidence, and component candidates. Require explicit component CAS mapping or withholding where source CAS applies to only one child; do not auto-broadcast a component CAS into accepted identities. Keep existing broadcast functionality for legitimate reviewed shared identifiers, but make identity correspondence explicit and auditable.
3. **Review safeguards:** R/mod_review_results.R and stage_review gain an explicit scope/conflict decision path with reason/evidence. Validate membership and source correspondence separately. Guard bulk accepts against unresolved scope/conflicts; VERIFIED alone does not resolve them. Display candidate and accepted identity distinctly, show blockers, and allow keep-as-aggregate without claiming one constituent represents the aggregate. Decision keys must include source/row lineage or a content signature when Name/CAS is ambiguous; error/report unmatched and ambiguous matches rather than silently applying a specific scope decision to all matching names.
4. **Persistence/replay:** extend mutable review field allowlists in R/code_generation.R, Session State in R/export_helpers.R, restore in R/config_import.R, headless inputs/docs, and generated replay scripts. Use content/evidence signatures to invalidate decisions when name, CAS, scope, selected ID, or relevant candidate evidence changes. A re-run must not inherit a resolved conflict from stale flags. Version/migrate new fields conservatively; old files retain candidates and flags and are never assumed to contain scope proof. Recompute accepted fields after retry merges and every review action.
5. **Exports and consumers:** use the policy in R/export_helpers.R and stage_export to add accepted fields/view and explicit excluded-row reasons/counts. Wire the accepted view into any new identity-only integration. For R/toxval_mapper.R, add a documented explicit accepted-identity mode and test that neither `dtxsid` fallback nor raw source CAS/name can restore a blocked candidate. Decide and document a release/migration path before changing the existing mapper default; its current audit exports must not be silently broken. When using accepted mode, preserve harmonized row alignment and report excluded/unaccepted rows rather than losing measurements unnoticed.
6. **Queue and completion:** R/curate_iterate.R must expose scope/source blockers for single/FOLLOW-UP rows and distinguish deliberate pending dispositions from accepted identities. Retain informative component candidates on single-source rows even though `get_resolution_options()` currently limits statuses. Avoid claiming zero ordinary pending picks means every source identity is accepted.
7. **Detection:** extend multi-analyte review heuristics for credible unspaced component lists (including both cited slash lists), preserving source text. Keep detection, suggestions, and precheck consistent. Do not simply replace all slashes or auto-split: units/ratios and protected chemical syntax remain negative cases. Explicit reviewer-marked scope conflicts must work even when detection misses a class such as Stilbenes.
8. **Documentation:** update roxygen/man/NAMESPACE for exported helpers, headless-curation vignette, replay examples, export docs, and NEWS. Include combined-name/single-component CAS, deliberate aggregate retention, explicit source conflict, and registered mixture acceptance examples.

## Meaningful regression cases

| Scenario | Required result |
| --- | --- |
| Unspaced and spaced Febantel/Fenbendazole/Oxfendazole plus injected component CAS hit | Candidate retained; scope review surfaced; accepted ID blank until explicit component/scope decision |
| Stilbenes with diethylstilbestrol CAS candidate and explicit scope blocker | No acceptance of representative compound solely from single CAS or VERIFIED |
| ALKYL PHENOL ETHOXYIATE with reported CAS candidate and explicit source-conflict record | Manual pick, registry existence, pinning, CLEAR, score, and bulk acceptance do not alone clear conflict |
| Genuine split with CAS belonging to only one component | Each child retains lineage; unmatched components do not inherit accepted component ID; correct child may be accepted after reviewed mapping |
| Keep combined as aggregate | Scope disposition retained and queue distinguishes deliberate pending identity; no component promoted |
| Verified registered mixture/extract with authoritative source and registry evidence pinned in a fixture | Combined source retains one accepted DTXSID without forced split; similar unverified candidate remains provisional |
| Clean substance with concordant sources or legitimate one-source lookup | Compatibility preserved when no blockers; no blanket exclusion of single matches |
| BAD, FOLLOW-UP, incoming needs_review, unresolved warning, disagree/error/unresolvable, unpinned suggestion, unknown status | Accepted ID blank with deterministic blocker reasons; BAD exclusion independent of existing needs_review semantics |
| Reviewed WQX name-only identity | Existing WQX review behavior preserved; no accepted DTXSID invented |
| Workbook/replay round trip, reordered/duplicate names, split lineage, rerun with changed CAS/candidates | Decisions target intended source rows; stale/ambiguous decisions reported and do not grant acceptance |
| Accepted ToxVal mode with both raw dtxsid fallback and blocked consensus ID present | Fallback cannot bypass gate; measurements and lineage remain aligned; audit candidates survive |
| Units, ratios, parenthetical alpha/beta, stereochemistry, legitimate slash syntax | No destructive normalization or automatic split |

Use deterministic captured lookup/evidence fixtures for package tests; live registry/SDS checks are a separate opt-in validation step. The reported Yucca/Orange examples are not yet suitable verified positive fixtures. Obtain an authoritative registry record and matching source composition/scope before choosing one, record provenance/date, and do not assert fresh chemical correctness from this audit CSV.
